# 毎日の新作を自動で作ってストックする（方法A：Claude Code の「ルーティン」）

Claude Code（https://claude.ai/code ）の「ルーティン」が毎日クラウドで動き、新作問題を作って GitHub の置き場所に追加します。
アプリは起動時に置き場所を見に行き、新しい日付の分を端末に保存して練習に混ぜます。
あなたが Claude を開いていなくても、PC の電源が切れていても動きます。

- 置き場所（GitHub）：https://github.com/tsunashiman/yomikai-proto
- アプリの公開先（公式の住所・さくらのレンタルサーバ）：https://yomikai.tsunashiman.com/ （GitHub の main に置くと GitHub Actions が自動でサーバーへ同期する。旧住所の GitHub Pages は引っ越し期間中だけ）
- 新作の受信元（アプリが見に行く場所）：https://yomikai.tsunashiman.com/stock/

## 全体の流れ

```
毎日 04:07 と 16:07（日本時間）
  ルーティン ──① 生成（plan が出すコマ：通常 100 文、各文に全パターンの問いと読解）──② 検査スクリプトで自己チェック
            ──③ stock/pending/翌日の日付.json に保存 ──④ 日付が来た pending を approved へ昇格
            ──⑤ GitHub（main）へ push ──⑥ 実行結果の要約を通知
アプリ起動時
  stock/index.json（approved の一覧）→ まだ持っていない日付のファイルを取得 → 端末に保存 → 練習の「新作」に合流
```

- 1日分＝練習用（速読30文・読解10問）＋ランキング用（速読14・読解6の20問）。作った当日は pending のまま（配信されない）。
  翌日の朝の実行で approved に上がり、アプリに届きます（配信は日付の前日。ランキング用20問を日付が変わった瞬間から全員に使えるようにするため）。
  この 1 日が「目視で止める時間」です。止めたい日付は `stock/hold.txt` に書くか、Claude に「10/5 の分は保留」と頼めば止まります。
- ランキング用の20問はその日付にだけ使われ、練習には混ざりません。練習用の新作は練習モードの「今日の新作」として出ます。
  ランキング用が無い日（受信できなかった端末も）は、アプリに最初から入っている基本問題から選んだ20問で代用されます。

## 仕組みの前提（済んでいること）

1. GitHub の無料アカウント（tsunashiman）と置き場所 yomikai-proto（公開）を作成済み。
2. Claude と GitHub を接続済み：Claude Code（claude.ai/code）で「GitHub アカウントを接続」→「Claude GitHub App をインストール」
   （Repository access は「Only select repositories」→ yomikai-proto）。
   ※ 接続の状態は GitHub の Settings → Applications → Installed GitHub Apps → Claude → Configure で確認・変更できます。
3. 「PWA公開用」フォルダの中身（stock/ と tools/ を含む）を置き場所に入れ、Settings → Pages で main /(root) を公開。

## ルーティンの作り方（claude.ai/code → 左の「ルーティン」→「新しいルーティン」）

- リポジトリ：tsunashiman/yomikai-proto
- スケジュール：毎日 04:07 と 16:07（日本時間）。ルーティン画面の「カスタム」の cron 式は UTC なので `7 7,19 * * *`（= 日本時間 16:07 と 04:07）。2026-10-02 に設定済み（画面の表示は「07:07 AM と 07:07 PM、毎日（時刻はUTC）」）
- 指示文：下の枠の中をそのまま貼る
- 通知（あれば有効に）：毎朝「今日はこの30文を作りました」の要約が届きます

## ルーティンの指示文（そのまま使えます。2026-10-02 改訂：1 日 2 回・各分野×各長さ 100 文の整備・問いの全パターン・他社AI確認用ファイル）

```
あなたは「論理的読解タイムアタック」の新作問題を作る担当です。1日2回（日本時間 4:07 と 16:07）動きます。日付は日本時間（JST）で考えてください。次を順に行い、最後に短く報告してください。

0. 作業場所：このセッションにはリポジトリ tsunashiman/yomikai-proto が用意されています。tools/ と stock/ があるフォルダ（リポジトリの直下）で作業します。無い場合は git clone https://github.com/tsunashiman/yomikai-proto.git で取得してその中に入ります。最初に git pull で最新にします。
1. tools/生成の指示文.md を読みます（形式・ルールはすべてそこに書いてあります）。次に
   python3 tools/stock_daily.py plan
   を実行し、出てきた cells（分野 g × 長さ lv と本数 n）のとおりに速読の文を作ります。1文ごとに、文中のあらゆる語を問う問い（単文3〜6・二節5〜8・三節と四節以上7〜12個）と、同じ本文に付ける読解（二節以上は2〜4問、単文は成立するものだけ1〜2問。1文に1つは「盲点」を突く角度を入れる。数や順序の計算が要る「ひねり」は1文に1つまでで "t":"twist" を付ける）を作ります。誤答は「紛らわしいが、正解を見れば納得できる」ものにします。
   日付は「明日（JST）」。その日付のファイルが stock/approved にすでにある場合は、その次のまだ無い日付にします（stock/pending にある場合は add で同じファイルに足されるので同じ日付でよい）。
   ランキング用 daily（速読14文＝A8/B3/C2/D1、読解6問＝B3/C2/D1。練習用とは別の本文。ひねりは入れない）は、その日付の pending にまだ daily が無いときだけ作ります（通常は朝の実行）。
   重複を避けるため tools/base_texts.json と stock/approved・stock/pending の本文には目を通します。実在の個人・企業・事件・政治の話題は使いません。
2. できた JSON をリポジトリ直下の new.json に保存し、
   python3 tools/stock_daily.py validate new.json
   を実行します。NG が 0 になるまで直します（「注意」もできる範囲で減らす）。すべての問いを自分で解き直し、答えが一つに決まること、ひねりの計算が合っていることを確かめます。
3. 合格したら順に実行します：
   python3 tools/stock_daily.py add new.json
   python3 tools/stock_daily.py plan advance
   python3 tools/stock_daily.py promote
   python3 tools/stock_daily.py review <作った日付>
   python3 tools/stock_daily.py push "新作 YYYY-MM-DD（n回目）"
   push は main ブランチに直接入れます。プルリクエストは作りません。終わったら new.json は削除します（stock/ 以外はコミットしません）。
4. 報告：作った日付と何回目か、作ったコマ（分野×長さ）と本数、速読の問いの総数・読解の総数・ひねりの数、ランキング用の有無、検査の注意の件数、本文の見本を3つ、approved に上がった日付、python3 tools/stock_daily.py plan status の残り合計、push の成否。
5. push できなかった場合（権限がない・拒否された）：new.json の中身をそのまま報告に添え、「GitHub に置けませんでした」と理由を書きます。
```

## 毎日の確認（任意・1分）

- 通知の要約を見て、おかしな文があれば `stock/hold.txt` にその日付を1行追加する（GitHub のサイト上で編集できます）。
  翌朝の実行で、その日付は approved に上がりません。直したいときは Claude に「10/5 の pending の○○を直して」と頼めます。
- アプリの「設定」→「新作の受信」に、受け取った文の数と最新の日付、最終確認の時刻が出ます。「今すぐ受信」で手動でも取りに行けます。
- 置き場所の中身は https://github.com/tsunashiman/yomikai-proto/tree/main/stock でいつでも見られます。

## 仕組みの注意

- 練習用は 1 回 100 文（各分野×各長さ 100 文がそろうまで。そのあとは毎日各コマ 3 文＝60 文）。1 文に速読の問いを 3〜12 個、読解を 1〜4 問付けます。
- ランキング用の20問は前日の朝から置き場所にあるため、見ようと思えば前日に見られます（試作段階では許容。販売時はサーバーで当日まで隠します）。
- 端末には受信した分をすべて保存します（1 日あたり 100〜250KB）。保存領域の切り替え（IndexedDB）を次の版で行います。
- 生成の質は「検査スクリプト（形式・正答の所在・重複）」＋「作った Claude 自身の解き直し」＋「翌日までの保留期間」の3段構えです。
  販売時には、別のモデルによる相互検査と、承認者が「承認」ボタンを押すまで配信しない運用（企画書 §4 の段階3）に切り替えます。
- Cowork（デスクトップアプリ）のスケジュールされたタスクは GitHub へ書き込めないため、書き込みができる Claude Code のルーティンを使います。
- 方法B（Claude API ＋ GitHub Actions）に移すときも、tools/ と stock/ の形式はそのまま使えます。
