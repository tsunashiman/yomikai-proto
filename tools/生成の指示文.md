# 新作問題の作り方（毎日の生成の指示文）

このファイルは、毎日の自動実行（Claude Code のルーティン）が読んで、その日の新作問題を作るための仕様です。
人が手で作るときも同じ形式で書けば、アプリにそのまま入ります。

## 1. 作るもの（1日分）

- 速読の文（`drills`）：**30 文**。長さの内訳は 単文 A×10、二節 B×8、三節 C×7、四節以上 D×5。
  各文に問いを **2〜3 個**（文の前半を問うものと後半を問うものを混ぜる）。
- 読解（`reads`）：**10 問**。二節 B×4、三節 C×3、四節以上 D×3（D のうち 1 問は矛盾探し `contra`。ときどき「矛盾なし `none:true`」も混ぜる）。
- 分野（`g`）は 5 つを全部使う：`daily` 日常会話 / `novel` 小説・エッセイ / `news` ニュース / `essay` 新聞・評論 / `culture` 教養（歴史・科学・経済・ことば）。
  目安は daily 9、novel 6、news 6、essay 5、culture 4（読解も同じ比率で）。
- **ランキング用（`daily`）：その日に全員が同じ順で解く 20 問**。速読 14 文（A×8、B×3、C×2、D×1、各文に問いを 2〜3 個）と
  読解 6 問（B×3、C×2、D×1。D は矛盾探し `contra` でもよい）。練習用（上の 30 文・10 問）とは別の本文で、分野は 3 種類以上を混ぜる。
  アプリは速読の各文から問いを 1 つ日付で機械的に選ぶので、どの問いが出ても成り立つように作る。
  ※ `daily` が無い日は、アプリに最初から入っている基本問題から選んだ 20 問で代用される（検査では「注意」になる）。

## 2. ファイルの形式（JSON）

```json
{
 "date": "2026-10-01",
 "drills": [
  { "lv": "A", "g": "daily", "text": "妹が赤い傘を買った。",
    "qs": [
      { "q": "誰が買った？", "a": "妹", "d": ["姉", "母", "弟"] },
      { "q": "傘は何色？", "a": "赤い", "d": ["青い", "黒い", "白い"] } ] },
  { "lv": "B", "g": "daily", "text": "兄は肉を焼き、妹はサラダを作った。",
    "qs": [
      { "q": "妹は何を作った？", "a": "サラダ", "d": ["スープ", "デザート", "ご飯"] },
      { "q": "兄は何をした？", "a": "肉を焼いた", "h": "肉を焼", "d": ["魚を焼いた", "皿を洗った", "買い物をした"] } ] }
 ],
 "reads": [
  { "lv": "B", "g": "daily", "kind": "entail", "text": "雨が降ってきたので、窓を閉めた。",
    "q": "この文から言えるのは？", "a": "窓を閉めたのは雨のため",
    "d": ["雨がやんだので窓を開けた", "窓を閉めたら雨が降った", "寒かったので窓を閉めた"],
    "why": "「ので」は理由を表す。窓を閉めた理由は雨。" },
  { "lv": "D", "g": "daily", "kind": "contra", "text": "彼は一度も海外に行ったことがないが、去年パリで買ったという時計を自慢し、来月もまた行くつもりだと言った。",
    "q": "この文でおかしいのは？", "a": "海外に行ったことがないのに、パリで時計を買っている",
    "d": ["来月もまた行くと言っている", "時計を自慢している"],
    "why": "「一度も海外に行ったことがない」と「去年パリで買った」は両立しない。" },
  { "lv": "D", "g": "daily", "kind": "contra", "none": true, "text": "店は正午に開くと張り紙にあり、私は11時半に着いて列に並び、開店と同時に一番に入って、限定のパンを買えた。",
    "q": "この文でおかしいのは？", "a": "",
    "d": ["正午開店なのに、11時半に店に入っている", "一番に入ったのに限定のパンが買えたのは変だ", "列に並んだのに開店と同時に入れたのは矛盾"],
    "why": "11時半に着いて並び、正午の開店と同時に入った。すべて両立する。" }
 ],
 "daily": {
  "drills": [ 14 本（形式は drills と同じ。A×8、B×3、C×2、D×1） ],
  "reads":  [ 6 問（形式は reads と同じ。B×3、C×2、D×1） ]
 }
}
```

`daily` の中身も drills / reads とまったく同じ形式（`lv` `g` `text` `qs` ／ `lv` `g` `kind` `text` `q` `a` `d` `why`）。

## 3. 速読の文（drills）のルール

- 本文の長さ：A 8〜18 字（「、」なし）、B 15〜35 字（「、」1 つ以上）、C 18〜53 字（「、」2 つ以上）、D 36〜75 字（「、」3 つ以上）。文末は「。」。
- **正答 `a` は本文にそのままの文字列で含める**（アプリが本文のその部分を光らせる）。活用で形が変わるときは、本文に含まれる部分を `h` に書く（例：a「肉を焼いた」h「肉を焼」）。
- 誤答 `d` は 3 個以上。**本文に含まれる語は誤答にしない**（正答が一つに決まらなくなる）。正答と同じ種類の語（人なら人、色なら色、数なら数）にして、長さもそろえる。
- 問いは「誰が／何を／どこで／いつ／いくつ／どうした／なぜ」など、本文の一か所を素直に問う。ひっかけや推測が要る問いは読解（reads）へ。
- 4 つ目の選択肢「上記以外」はアプリが自動で足すので書かない（正答を選択肢から外す回もアプリが自動で作る）。
- 本文は自然で具体的な日本語。固有名詞は一般的なもの（駅名・地名・商品名は架空でよい）。実在の個人名・企業名・政治的な話題・事故や事件の当事者は使わない。ニュース分野は「ありそうな出来事」を架空で書く（実際の最新ニュースを断定しない）。
- 同じ本文・ほぼ同じ本文を繰り返さない。`tools/base_texts.json`（最初から入っている文）と `stock/` の既存ファイルにある本文は使えない（検査スクリプトが弾く）。

## 4. 読解（reads）のルール

- `kind: "entail"`：文から**言えること／言えないこと**、理由、状況、要旨を問う。正答は本文の言い換え・含意で、**本文にそのまま書かれていない**表現にする。誤答は「順番を逆にした」「原因と結果を入れ替えた」「書かれていないことを足した」の 3 タイプを混ぜる。4 つ目の「上記以外」はアプリが足す。
- `kind: "contra"`（矛盾探し・D のみ）：本文の中で両立しない 2 か所を作り、正答 `a` にその矛盾を短く書く。誤答 `d` は 2〜3 個で、本文に書いてあるが矛盾ではないこと。4 つ目の「おかしい箇所はない」はアプリが足す。
  `none: true` のときは矛盾がない文にして、`a` は空文字、`d` に「矛盾に見えるが両立すること」を 3 個書く。
- `why`（解説）は 1〜2 文で、なぜその答えになるかを本文の言葉を引いて説明する（答え合わせ画面に出る）。
- 長さ：B 15〜35 字、C 18〜45 字、D 40〜80 字。

## 5. 自分で確かめること（提出前のチェック）

1. `python3 tools/stock_daily.py validate <ファイル>` が「合格」になるまで直す（NG は必ず直す。注意もできるだけ減らす）。
2. 各問いを自分で解いてみて、**正答が一つに決まる**か、誤答のどれかが「これも正しい」と読めないかを確認する。
3. 速読の問いは「本文を一度読めば答えられる」か。知識がないと解けない問いにしない。
4. 読解の正答が本文の丸写しになっていないか。矛盾探しの矛盾が本当に両立しないか。
5. 5 分野・4 つの長さがそろっているか。人物は男女・年齢・立場に偏りがないか。差別的・暴力的・性的な表現、特定の個人や団体を思わせる表現がないか。
6. ランキング用（daily）が 14 文＋6 問の内訳どおりで、練習用と本文が重なっていないか。

## 6. できあがったら

```
python3 tools/stock_daily.py add   stock/pending/YYYY-MM-DD.json   # 検査して pending へ
python3 tools/stock_daily.py promote                              # 明日（日本時間）以前の日付の pending を approved へ（hold.txt の日付は保留）
python3 tools/stock_daily.py push "新作 YYYY-MM-DD"               # GitHub へ
```

アプリは `stock/index.json` の approved に載った日付のファイルだけを受け取る。pending にある間は配信されない。
翌日分は前日の朝に approved に上がる（ランキング用の 20 問を日付が変わった瞬間から全員に使えるようにするため）。

すでにある日付のファイルにランキング用だけを足す（差し替える）とき：
```
python3 tools/stock_daily.py daily YYYY-MM-DD <daily だけを書いた JSON>   # {"drills":[14本],"reads":[6問]} を入れて検査
```
