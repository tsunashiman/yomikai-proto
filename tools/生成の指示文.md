# 新作問題の作り方（毎日の生成の指示文）

このファイルは、毎日の自動実行（Claude Code のルーティン）が読んで、その日の新作問題を作るための仕様です。
人が手で作るときも同じ形式で書けば、アプリにそのまま入ります。

## 1. 作るもの（1 回の実行分）

2026-10-02 から、練習用の文は「各分野×各長さ 100 文」をそろえる計画で作る（基本の文を含む）。1 回の実行で作る分は
`python3 tools/stock_daily.py plan` が出す（JSON）。`cells` の各コマ（分野 g × 長さ lv）について `n` 文ずつ作る（通常は 10 コマ × 10 文＝100 文）。
順番は 分野1の各長さ → 分野2の各長さ → … で、コマが 100 文に達したら飛ばされる。全コマがそろったあとは `mode: "maintenance"`
（毎日各コマ 3 文＝60 文、朝の実行だけ）になる。

- 速読の文（`drills`）：plan のとおりの本数。**1 文につき、文中のあらゆる語を問う問いを付ける**（単文 3〜6 個、二節 5〜8 個、三節・四節以上 7〜12 個）。
- 読解（`reads`）：**同じ本文に付ける**（独立の文は作らない）。二節以上は 1 文に 2〜4 問、単文は 1〜2 問（読解として成立するものだけ。成立しなければ 0 でよい）。
- 分野（`g`）：`daily` 日常会話 / `novel` 小説・エッセイ / `news` ニュース / `essay` 新聞・評論 / `culture` 教養（歴史・科学・経済・ことば）。
- **ランキング用（`daily`）：その日に全員が同じ順で解く 20 問**（1 日 1 回、朝の実行で作る。2 回目の実行では作らない）。速読 14 文（A×8、B×3、C×2、D×1、各文に問いを 2〜3 個）と
  読解 6 問（B×3、C×2、D×1。D は矛盾探し `contra` でもよい）。練習用とは別の本文で、分野は 3 種類以上を混ぜる。
  アプリは速読の各文から問いを 1 つ日付で機械的に選ぶので、どの問いが出ても成り立つように作る。ひねりの問いはランキング用には入れない。
  ※ `daily` が無い日は、アプリに最初から入っている基本問題から選んだ 20 問で代用される（検査では「注意」になる）。
- 1 日 2 回の実行（04:07 と 16:07）：どちらも日付は「明日（JST）」。2 回目は同じ日付の pending に `add` で足される（本文の重複は検査で弾かれる）。

## 2. ファイルの形式（JSON）

```json
{
 "date": "2026-10-01",
 "drills": [
  { "lv": "A", "g": "daily", "text": "妹が赤い傘を買った。",
    "qs": [
      { "q": "誰が買った？", "a": "妹", "d": ["姉", "母", "弟"] },
      { "q": "傘は何色？", "a": "赤い", "d": ["青い", "黒い", "白い"] } ] },
  { "lv": "B", "g": "daily", "text": "兄は肉を焼き、妹はサラダを作った。",
    "qs": [
      { "q": "妹は何を作った？", "a": "サラダ", "d": ["スープ", "デザート", "ご飯"] },
      { "q": "兄は何をした？", "a": "肉を焼いた", "h": "肉を焼", "d": ["魚を焼いた", "皿を洗った", "買い物をした"] } ] }
 ],
 "reads": [
  { "lv": "B", "g": "daily", "kind": "entail", "text": "雨が降ってきたので、窓を閉めた。",
    "q": "この文から言えるのは？", "a": "窓を閉めたのは雨のため",
    "d": ["雨がやんだので窓を開けた", "窓を閉めたら雨が降った", "寒かったので窓を閉めた"],
    "why": "「ので」は理由を表す。窓を閉めた理由は雨。" },
  { "lv": "D", "g": "daily", "kind": "contra", "text": "彼は一度も海外に行ったことがないが、去年パリで買ったという時計を自慢し、来月もまた行くつもりだと言った。",
    "q": "この文でおかしいのは？", "a": "海外に行ったことがないのに、パリで時計を買っている",
    "d": ["来月もまた行くと言っている", "時計を自慢している"],
    "why": "「一度も海外に行ったことがない」と「去年パリで買った」は両立しない。" },
  { "lv": "D", "g": "daily", "kind": "contra", "none": true, "text": "店は正午に開くと張り紙にあり、私は11時半に着いて列に並び、開店と同時に一番に入って、限定のパンを買えた。",
    "q": "この文でおかしいのは？", "a": "",
    "d": ["正午開店なのに、11時半に店に入っている", "一番に入ったのに限定のパンが買えたのは変だ", "列に並んだのに開店と同時に入れたのは矛盾"],
    "why": "11時半に着いて並び、正午の開店と同時に入った。すべて両立する。" }
 ],
 "daily": {
  "drills": [ 14 本（形式は drills と同じ。A×8、B×3、C×2、D×1） ],
  "reads":  [ 6 問（形式は reads と同じ。B×3、C×2、D×1） ]
 }
}
```

`daily` の中身も drills / reads とまったく同じ形式（`lv` `g` `text` `qs` ／ `lv` `g` `kind` `text` `q` `a` `d` `why`）。

## 3. 速読の文（drills）のルール

- 本文の長さ：A 8〜18 字（「、」なし）、B 15〜35 字（「、」1 つ以上）、C 18〜53 字（「、」2 つ以上）、D 36〜75 字（「、」3 つ以上）。文末は「。」。
- **正答 `a` は本文にそのままの文字列で含める**（アプリが本文のその部分を光らせる）。活用で形が変わるときは、本文に含まれる部分を `h` に書く（例：a「肉を焼いた」h「肉を焼」）。
- 誤答 `d` は 3 個以上。**選択肢の中で正しいものは必ず 1 つだけ**（正答が 2 つ以上あってはいけない）。誤答はどれも本文に照らして明確に誤りにする（アプリは正答を抜いて「上記以外」を正解にする回も作るので、誤答のどれかが正しいと正解が 2 つになる）。**本文に含まれる語は誤答にしない**（正答が一つに決まらなくなる）。正答と同じ種類の語（人なら人、色なら色、数なら数）にして、長さもそろえる。
- 問いは「誰が／何を／どこで／いつ／いくつ／何番目／何色・どんな／どのように／なぜ／結局どうした」など、**文中のあらゆる語を 1 つずつ問う**（同じ正答を問う問いは 2 つ作らない。言い回しは変える）。ひっかけや推測が要る問いは読解（reads）へ。
- 誤答は「**紛らわしいが、正解を見れば確かにそうだと納得できる**」もの：正答と同じ種類で一つだけ違う（三日前↔二日前、寺院↔神社・役所、行けなかった↔行った・行きたかった）。消去法ですぐ分かる誤答や、正答の言い換えは使わない。
- 数や順序の計算が要る「ひねり」の問いは、速読では正答が本文に含まれる必要があるので基本的に読解（reads）側に置く。速読側に置く場合も 1 文に 1 つまでで `"t": "twist"` を付ける。
- 4 つ目の選択肢「上記以外」はアプリが自動で足すので書かない（正答を選択肢から外す回もアプリが自動で作る）。
- 本文は自然で具体的な日本語。固有名詞は一般的なもの（駅名・地名・商品名は架空でよい）。実在の個人名・企業名・政治的な話題・事故や事件の当事者は使わない。ニュース分野は「ありそうな出来事」を架空で書く（実際の最新ニュースを断定しない）。
- 同じ本文・ほぼ同じ本文を繰り返さない。`tools/base_texts.json`（最初から入っている文）と `stock/` の既存ファイルにある本文は使えない（検査スクリプトが弾く）。

## 4. 読解（reads）のルール

- `kind: "entail"`：文から**言えること／言えないこと**、理由、状況、要旨を問う。**正解は本文だけを見て導けるものにする**（本文に書かれていない知識・前提・推測が要る問いは作らない）。正答は本文の言い換え・含意で、**本文にそのまま書かれていない**表現にする。**選択肢の中で正しいものは 1 つだけ**にし、誤答 3 個はどれも本文に照らして明確に誤りにする（本文から言えてしまう誤答は不可）。誤答は「順番を逆にした」「原因と結果を入れ替えた」「書かれていないことを足した」の 3 タイプを混ぜる。4 つ目の「上記以外」はアプリが足す。
- `kind: "contra"`（矛盾探し・D のみ）：本文の中で両立しない 2 か所を作り、正答 `a` にその矛盾を短く書く。誤答 `d` は 2〜3 個で、本文に書いてあるが矛盾ではないこと。4 つ目の「おかしい箇所はない」はアプリが足す。
  `none: true` のときは矛盾がない文にして、`a` は空文字、`d` に「矛盾に見えるが両立すること」を 3 個書く。
- `why`（解説）は 1〜2 文で、なぜその答えになるかを本文の言葉を引いて説明する（答え合わせ画面に出る）。
- **本文は速読の文と同じにする**（`text` を一字違わず同じにし、`lv`・`g` も同じ）。同じ本文に複数の読解を付けてよい（質問文は変える）。単文（A）にも、成立するなら付ける。
- 問いの種類をいろいろ混ぜる：「この文から言えるのは？」「言えないのはどれ？」「なぜ〜したと考えられる？」「〜はどうなった？」「この場面の状況として正しいのは？」「筆者の考えに合うのは？」。
  **「その内容を問うのか。盲点だった」と感じる角度を 1 文に 1 つは入れる。** 誤答は「もっともらしいが、本文を正確に読むと違う」もの（原因と結果の入れ替え、否定の反転、言い過ぎの断定、別の人物・時・場所へのすり替え）。
- 数や順位・時間の計算が要る「ひねり」の問い（例：「参加国32か国中、日本は23位だった。」→「順位は下から何番目？」a「10番目」d「9番目」「8番目」「11番目」why「下から（32−23+1）番目」、
  「日本より順位が上の国は何か国？」）は意外性があってよいが、**1 文に 1 つまで**。`"t": "twist"` を付ける（アプリが出す頻度を抑える）。計算は必ず検算する。
- 長さ：本文は速読の文と同じなので、速読の長さの範囲に従う。

## 5. 自分で確かめること（提出前のチェック）

1. `python3 tools/stock_daily.py validate <ファイル>` が「合格」になるまで直す（NG は必ず直す。注意もできるだけ減らす）。
2. 各問いを自分で解いてみて、**選択肢のうち正しいものがちょうど 1 つ**か（正答が 2 つ以上になっていないか）、誤答のどれかが「これも正しい」と読めないかを確認する。
3. 速読の問いは「本文を一度読めば答えられる」か。知識がないと解けない問いにしない。
4. 読解は本文だけを見て正答が導けるか（外の知識や推測が要るものは不可）。正答が本文の丸写しになっていないか。矛盾探しの矛盾が本当に両立しないか。
5. 5 分野・4 つの長さがそろっているか。人物は男女・年齢・立場に偏りがないか。差別的・暴力的・性的な表現、特定の個人や団体を思わせる表現がないか。
6. ランキング用（daily）が 14 文＋6 問の内訳どおりで、練習用と本文が重なっていないか。

## 6. できあがったら

```
python3 tools/stock_daily.py plan                                  # この実行で作るコマと本数（最初に見る）
python3 tools/stock_daily.py validate new.json                     # NG が 0 になるまで直す
python3 tools/stock_daily.py add   new.json                        # 検査して pending へ（同じ日付が pending にあれば足される）
python3 tools/stock_daily.py plan advance                          # 作ったコマのぶん計画を進める（add が成功したときだけ）
python3 tools/stock_daily.py promote                               # 明日（日本時間）以前の日付の pending を approved へ（hold.txt の日付は保留）
python3 tools/stock_daily.py review YYYY-MM-DD                     # 他社AI確認用ファイル（stock/review/<日付>_他社AI確認用.md と latest.md）
python3 tools/stock_daily.py push "新作 YYYY-MM-DD"                # GitHub へ（stock/ の下だけがコミットされる）
```

アプリは `stock/index.json` の approved に載った日付のファイルだけを受け取る。pending にある間は配信されない。
翌日分は前日の朝に approved に上がる（ランキング用の 20 問を日付が変わった瞬間から全員に使えるようにするため）。
作ってから配信までの約 1 日が、人が見て止められる時間（`stock/hold.txt` に日付を書けば上がらない）。

すでにある日付のファイルにランキング用だけを足す（差し替える）とき：
```
python3 tools/stock_daily.py daily YYYY-MM-DD <daily だけを書いた JSON>   # {"drills":[14本],"reads":[6問]} を入れて検査
```

他社AI確認用ファイル（`stock/review/`）は、その日の文・問い・選択肢・解説を、他社の AI にそのまま見せて点検を頼める形（依頼文と報告の形式つき）にしたもの。
利用者はファイルの中身か URL（https://tsunashiman.github.io/yomikai-proto/stock/review/latest.md）を他社 AI に渡し、返ってきた報告を Claude に貼り付ける。
